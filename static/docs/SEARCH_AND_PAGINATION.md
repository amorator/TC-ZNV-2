# Поиск и пагинация: поведение

В проекте используется единый подход к поиску и пагинации через параметры URL. Сохранение состояния в LocalStorage для поиска убрано — теперь состояние определяется адресной строкой.

## Общие правила

- Поиск сохраняется в URL с помощью явных параметров.
- Очистка поиска удаляет только свой параметр `q` и при необходимости восстанавливает пагинацию.
- Параметры пагинации отражаются в URL и сохраняются при мягких перезагрузках.
- Встроенные `onclick` у кнопок очистки не используются; обработчики навешиваются через `addEventListener`.

## Страницы

### Пользователи (`/users`)
- Параметр поиска: `q`
- Параметры пагинации: `page`, `page_size`
- Поведение:
  - Ввод в поле поиска обновляет `q` и может скрывать пейджер на время поиска.
  - Очистка поиска удаляет `q`, возвращает пейджер, сохраняет/восстанавливает `page`/`page_size`.
  - Клики по пейджеру обновляют `page`/`page_size` в URL и учитываются при перезагрузке.

### Группы (`/groups`)
- Параметр поиска: `q`
- Параметры пагинации: `page`, `page_size`
- Поведение идентично «Пользователям».

### Наряды (`/orders`)
- Параметр поиска: `q`
- Параметры пагинации: `page`, `page_size`
- Поведение:
  - Кнопка очистки удаляет `q`, при этом сохраняются `page`/`page_size`, таблица перерисовывается.
  - Используется дебаунс запросов по вводу.

### Файлы (`/files`)
- Параметр поиска: `q`
- Параметры пагинации: `page`, `page_size`
- Поведение:
  - Поиск обновляет `q`, а также актуальные `page` и `page_size` в URL.
  - Очистка удаляет `q` и перерисовывает список, сохраняя состояние пагинации в URL.

### Категории (`/categories`) и Регистраторы (`/registrators`)
- Два независимых поля поиска и два пейджера: для групп и для пользователей.
- Параметры URL:
  - Группы: `q_groups`, `page_groups`, `page_size_groups`
  - Пользователи: `q_users`, `page_users`, `page_size_users`
- Поведение:
  - Каждое поле восстанавливается из своего `q_*` и обновляет только его при вводе/изменении.
  - Очистка удаляет только свой `q_*` и перерисовывает соответствующую таблицу.
  - Пагинация одной таблицы не сбрасывает поиск/пагинацию другой.
  - Общий `q` удаляется, когда используется `q_groups` или `q_users`.
- Значения по умолчанию при навигации:
  - Ссылки верхнего меню на `/categories` и `/registrators` дополняются параметрами, если их нет:
    - `page_groups=1&page_size_groups=10&page_users=1&page_size_users=10`
  - При первом входе на эти страницы недостающие параметры добавляются к текущему URL.

## DOM и обработка событий

- Кнопки очистки навешиваются через `addEventListener` (при необходимости в capture-фазе), инлайн-обработчики удаляются.
- Для `input` используется дебаунс, чтобы снизить нагрузку.
- Делегирование кликов обеспечивает устойчивость при динамической перерисовке элементов.

## Backend: ожидания

- Эндпоинты принимают `q`, `page`, `page_size`:
  - `/api/users`, `/api/groups`, `/files/search`, `/api/orders/search`
- Для «Категорий/Регистраторов» используются `/api/users` и `/api/groups`, при этом клиент передаёт `q` из соответствующих `q_*`.

## Примечания

- Обновления URL выполняются через `window.history.replaceState`, чтобы избежать полной перезагрузки.
- Нормализация пагинации гарантирует наличие явных `page` и `page_size` в ссылках пейджера.
